# 04 — UX spec

**Who:** someone who tapped a WhatsApp forward on a mid-range Android or an iPhone, one-handed, 4G, wants a story image in under a minute. **Design for them only.** Desktop gets a centered 430px column, nothing more.

## Design tokens (`src/styles/tokens.css`)
```css
:root {
  --bg: #0E0A0C;          /* warm near-black, templates glow on it */
  --surface: #1A1316;
  --surface-2: #261C20;
  --text: #F7F1EA;
  --text-dim: #B8ADA6;
  --accent: #F0B32E;      /* saffron gold */
  --accent-ink: #1A1100;  /* text on accent */
  --danger: #FF5A5F;
  --radius: 16px; --radius-lg: 24px;
  --space-1: 4px; --space-2: 8px; --space-3: 12px; --space-4: 16px; --space-6: 24px; --space-8: 32px;
  --font-ui: 'DM Sans Variable', system-ui, sans-serif;
  --tap: 52px;            /* minimum tap target height */
}
```
Light mode is **not** supported in v1. Dark only. Set `<meta name="theme-color" content="#0E0A0C">`.

Type scale (UI): 32/700 title, 20/600 section, 16/400 body, 14/400 caption. Line height 1.3.
Buttons: primary = accent bg, ink text, 52px tall, full width, radius 16, 17/600. Secondary = surface-2 bg, text color. Ghost = text only.
Motion: 180 ms ease-out for state changes, spring (stiffness 300, damping 28) for cards. Honour `prefers-reduced-motion`.

```
│ Chamak        [privacy]│  top bar, 56px
│                              │
│  ┌──┐ ┌──┐ ┌──┐              │  hero: 3 template previews with sample
│  │  │ │  │ │  │   (auto     │  photos, 9:16 cards, auto-cycling
│  └──┘ └──┘ └──┘   cycling)  │  every 2.5s, no controls
│                              │
│  Festive frames for your     │  32/700
│  photos. 30 seconds. Free.   │
│  No signup. Photos never     │  16 dim
│  leave your phone.           │
│                              │
│ [ Add your photos  📷 ]      │  primary, sticky bottom, safe-area aware
│   3 to 8 photos · JPG/PNG    │  caption
└──────────────────────────────┘
```
- The button is a `<label>` wrapping `<input type="file" accept="image/*" multiple>`. No separate landing page, no "Create" step.
- After selection: inline progress ("Preparing 3 of 8…"), thumbnails appear as they finish, then auto-advance to Pick.
- Errors: < 3 photos → "Add at least 3 photos" inline, keep picked ones, button becomes "Add more". > 8 → take first 8, toast "Using your first 8 photos". Non-image → skipped silently with toast.

## Screen 2 — Pick (step `pick`)
```
┌──────────────────────────────┐
│ ‹ Photos   Pick a frame  ⊞   │  ⊞ = See all (grid sheet)
│                              │
│      ┌────────────────┐      │  card stack: top card 86% width,
│      │                │      │  9:16, user's photos rendered in,
│      │   (template    │      │  next card peeks 8px behind
│      │   with YOUR    │      │
│      │   photos)      │      │
│      │                │      │
│      └────────────────┘      │
│         ● ○ ○ ○              │  dots = position in pack
│  Garba Night · Navratri Pop  │  name + direction, 14 dim
│                              │
│ [ ✕ ]   [ Use this frame ]   │  ghost skip (next) + primary
└──────────────────────────────┘
```
- Swipe left = next, right = previous. Card tilts `offset/20` deg while dragging. Commit at 100px or velocity 500.
- Locked template: card shows normally with a small pill "🔒 Share to unlock" top-left. "Use this" becomes "Unlock by sharing" and opens a sheet: "Share Chamak once, or download 3 times, to unlock 4 bonus frames" with a "Share link on WhatsApp" button (`wa.me` text link). A `wa.me` text share cannot be verified, so it does **not** count; only `navigator.share` success or 3 downloads count.
- "See all" (⊞): bottom sheet, 2-column grid of cached thumbnails, pack sections ("Navratri", "Diwali"), tap = select + close.
- First-open hint, once per device: "Swipe to browse" with an animated hand, dismissed on first swipe. Stored in `localStorage` key `ck.hint`.
- Card previews use the Smart Pick assignment. Render each card lazily, 360x640, cache per template.

## Screen 3 — Edit (step `edit`)
```
┌──────────────────────────────┐
│ ‹ Frames     Edit     [Done] │
│ ┌──────────────────────────┐ │  canvas, full width minus 16px,
│ │                          │ │  9:16, touch-action: none
│ │     tap a photo to       │ │  selected slot = 3px accent ring
│ │     adjust               │ │
│ └──────────────────────────┘ │
│  ↻ ───────●───────  0°       │  rotate slider, only when slot selected
│ [Swap] [Smart Pick] [Shuffle]│  52px chips
│ ┌──┐┌──┐┌──┐┌──┐┌──┐┌──┐    │  photo strip (horizontal scroll), shown
│ └──┘└──┘└──┘└──┘└──┘└──┘    │  only after Swap; tap = put in slot
└──────────────────────────────┘
```
- Pinch zooms selected slot (1x–4x), drag pans, slider rotates ±45°. Double-tap slot = reset transform.
- **Swap**: opens the strip; tapping a photo assigns it to the selected slot (and if it was in another slot, swaps them).
- **Smart Pick**: re-runs best-score assignment. **Shuffle**: random among top half. Both animate a 180 ms crossfade.
- Nothing selected → hint text "Tap a photo to adjust" over the canvas, fades after first tap.
- "Done" renders HD and moves to Done screen with a 400–1500 ms "Rendering HD…" overlay.

## Global
- Top bars 56px, back chevron 44px tap area. Safe-area insets via `env(safe-area-inset-*)`.
- Toasts: bottom, 2.5 s, one at a time.
- Offline: the app works offline after first load (Vite PWA is **out of scope**; just don't fetch anything at runtime).
- Accessibility: all buttons have labels; canvas has `aria-label="Preview of your frame"`; focus rings visible; contrast ≥ 4.5:1 for text on bg.
- Copy voice: short, warm, Hinglish-friendly. Yes: "Shubh Navratri", "Ready ✨", "Photos never leave your phone." No: "Leverage", "AI-powered", exclamation marks everywhere.
- Error fallback (export failure twice): "Couldn't render on this phone. Try fewer photos." + button "Use 4 photos".
